How a planned Run is executed and recorded (apps/api/src/runs/). The driver app's offline outbox replays three kinds of items: `action` -> POST /runs/:id/actions (start, arrive, board, depart, end), `gps` -> POST /runs/:id/gps or the Socket.IO `gps` message, `fare` -> POST /runs/:id/fares. RunsService.applyOne applies each action under the dispatch wave lock, updates Run/RunStop/RideRequest state (boardedAt, no_show, done), appends an idempotent RunEvent and outbox notifications, broadcasts `run` status, and on `end` triggers the GPS verification used by settlement. Fares become immutable cash_fare Payments.
