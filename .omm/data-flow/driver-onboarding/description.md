Driver onboarding data path (apps/api/src/drivers/, storage/, driver-requirements/). A driver signs in with phone + SMS one-time code (OtpCode, bcrypt hashed, 5 min TTL); the first sign-in creates a User (role driver) and a draft DriverProfile in the chosen university. The driver fills the application (name, vehicle type, plate, seats, model year) and uploads each document the office requires (DriverRequirementSet) as multipart (JPEG/PNG/WebP/PDF, max 8 MB); bytes go to private disk storage, metadata to DriverDocument. Submit checks nothing is missing and moves the profile to pending; the office reviews documents through short-lived HMAC-signed links (every issuance logged in DocumentAccess) and approves/rejects/suspends. Students see the assigned driver's vehicle photo through the same signed-link mechanism.
