Who can use the system. identity/: student sign-in and activation via a pluggable IdentityProvider chosen per university from integrationConfig.identity (manual roster by default, HTTP API or OIDC), bcrypt passwords. students/: student profiles, gathering point choice. drivers/: phone OTP sign-in (Iraqi phone normalization), driver application lifecycle (draft -> submitted -> approved etc. in driver-rules.ts), document upload checked against driver-requirements. users/: office user listing. storage/: private disk storage for driver documents served by short-lived HMAC-signed links (GET /files/:token).
